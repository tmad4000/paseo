# Fork icon

`source.svg` is the self-contained artwork source. It preserves the upstream mark and adds a blue fork badge with contrasting rings. Badge color `#294ac4` is the **provisional** Ideaflow accent from index.ideaflow.app, approved by root d3caa262 for this icon task; Jacob can override it. `upstream.png` is the unmodified comparison reference, not a generation input.

Use Python 3.12 with Cairo installed, create an isolated virtual environment, install `requirements.txt`, then run `nice -n 19 python scripts/generate-fork-icons.py`. Pass `--check` to verify all generated outputs and the SHA-256 manifest without writing. No app dependencies change. Browser SVGs select 16/32 px symbols with viewport media queries; CairoSVG raster generation strips those media selectors and chooses the optical symbol explicitly after padding, preventing duplicate badges.

The generator writes the existing desktop, mobile and web identity asset paths. At 16 and 32 px the source SVG’s size-specific `small-badge-16` and `small-badge-32` symbols replace the detailed badge after platform padding, with a solid blue disc, bold white Y and one white contrast ring. The larger badge is smaller and positioned below the main contour cues. macOS exports have an optical inset and rounded tile. iOS uses an opaque full canvas (Expo generates the native Paseo AppIcon set during prebuild); Android adaptive foregrounds place the full mark and badge inside the central 66/108 safe circle. Legacy round and PWA maskable compositions also preserve the badge inside their safe circles; `mask-check.json` records automated coverage checks. Buzz mobile consumes the already-inset foreground directly, avoiding an extra inset. Status favicons retain their status colors at the opposite corner. The main contact sheet compares upstream and actual macOS exports at native 16, 32, 64, 128 and 1024 pixels on light and dark backgrounds. Additional `contact-sheet-*.png` files show generated web, iOS, Android, PWA and masked outputs at those same sizes. Circle/squircle previews and unmasked review samples are in `previews/`; these are raster/mask inspections, not device screenshots.

Linux checks validate generated pixels and containers. They do not establish actual Dock, menu bar or home-screen behavior on Apple devices.
