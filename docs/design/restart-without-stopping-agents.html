Paseo restart/update without stopping agents

Sol · 15 November 2026 · fork baseline 146f6e424 (initial inspection 135a3b4c9) · Linux investigation; Apple behavior requires Apple verification.

Answer

Restarting the desktop UI need not stop agents. Replacing the daemon worker currently does. Recommend a staged hybrid: first allow desktop updates to retain the existing daemon behind an opt-in setting; then add safe daemon draining and session restoration; use an independent agent host when actual uninterrupted daemon replacement is required.

Why processes die today

The supervisor owns a daemon worker, but provider runtimes still belong to that worker. bootstrap.ts: stop() freezes ingress/registration, closes all managed sessions, flushes storage, shuts down providers and calls terminalManager.killAll(). Claude session.close() ends its input, closes/interrupts the SDK query and terminates its entire process tree. Codex transport disposal closes its readline and stdin, rejects pending RPCs, and sends SIGTERM followed by SIGKILL after a deadline through terminateWithTreeKill. That helper enumerates descendants via tree-kill, with direct-child fallback; preservation cannot rely on a new process group alone.

These are deliberate cleanup actions, not a Linux rule that every child automatically dies when its parent exits. Simply removing cleanup or calling unref/detached is insufficient: stdio pipes and pending protocol state belong to the old daemon, EOF ends the input channel, output has no durable reader, permissions and turn events lose their owner. PTY masters similarly need a persistent owner. The supervisor also escalates to a process-tree kill if worker shutdown exceeds its deadline.

Desktop update IPC currently explicitly stops its captured, app-owned daemon before installing. Ordinary quit has a separate keepRunningAfterQuit rule. Startup also has version-mismatch replacement logic. A preservation option must cover all three paths, and must never take ownership of someone else's daemon.

What survives

Paseo agent identity, workspace, metadata, persisted timeline and provider persistence handles remain on disk. Claude session IDs and Codex thread IDs permit a fresh provider runtime to load saved conversation history. They do not serialize active tool processes, pending promises, in-memory permissions, SDK streams, background shells/watchers or an unfinished response. A resume prompt can repeat an external side effect; it is not continuation of the same running turn.

Options and effort

Option Behavior and risks Estimated agent-hours
A: drain and resume Wait for running/initializing/permission work, fence new turns at a quiet boundary, persist resident handles, flush, replace, reload handles without sending a new prompt. Never force restart on timeout. Idle Claude can own background work, and terminals remain vulnerable; must disclose those limits. Recovery from an already interrupted turn needs explicit policy rather than blind replay. 12–24 implementation + 6–12 integration/review
B: independent agent host Move provider adapters, pipes, permissions and durable event journal into a stable authenticated local process. Daemon reconnects by opaque persisted handles with sequence replay, fencing and version negotiation. Host owns agent process trees; worker shutdown cannot kill them. PTY/tmux can preserve terminal sessions, but cannot alone reattach JSON SDK protocol and in-memory state. 50–90 implementation + 20–35 failure/platform tests
Hybrid, recommended Opt-in desktop-only update preservation now: retain daemon, sessions and terminals unchanged; reconnect UI. Daemon version stays old until separately restarted. Follow with A for safe scheduled host upgrades, B for uninterrupted host upgrades. 6–12 first slice + above later phases

Upstream, checked today

Upstream main at 685e1133 has restart recovery: capture running records before close, repair persisted status at startup and dispatch a configured recovery prompt for eligible sessions. Its bootstrap still closes every agent. This recovers conversations after interruption; it does not retain live turns. Reuse its design where compatible rather than presenting resume as uninterrupted execution. No upstream merge or dependency update is part of this investigation.

Delivery and verification

The desktop setting “Keep agents running across app restarts” merged in PR #225. It retains the existing daemon across app updates; the daemon keeps its old version. The first upgrade from an older app cannot use this setting. Linux process survival was verified with an isolated real Codex turn and a replacement app owner. Apple installer behavior remains unverified.

The second slice implements A behind the startup setting daemon.gracefulRestart: true (deployment override PASEO_GRACEFUL_RESTART=1). It waits up to five minutes, fences at a quiet boundary, checkpoints resident handles, then replaces the supervised worker. The replacement restores handles without sending prompts; durable queues resume. Timeout keeps the daemon running. Failed provider restores remain visible and retryable. See the lifecycle contract for limits. Regression coverage includes permission responses, initialization, competing operations, install failure, queues and partial provider restoration. The opt-in Linux test uses a private HOME/PASEO_HOME and a real file-gated Codex turn across an actual worker replacement.
