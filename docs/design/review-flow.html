01 · review-ready-expand

Expand in place, with names visible immediately

First slice: a maximum of three named review rows beneath the workspace, plus “+N more.” Clicking a row reveals that exact agent, even when another session has higher attention priority.

Keep the count when collapsed and save that choice on the device. Search keeps its existing matching rows, so the review preview does not duplicate search results. Finished siblings remain visible beneath a workspace whose overall state is Working.

Why this default: fully collapsed hides the answer; fully expanded can bury other workspaces. A bounded preview provides identity without turning every workspace into a long tree.

02 · review-tab-sort

Stable tabs, purposeful review order

Today: top tabs follow stored pane order, usually insertion order with drag reordering. Some actions insert beside a related tab. They do not sort by completion time.

Sidebar workspace sorting is separate: Latest conversation activity, Your last message, AI’s last reply, Manual order, or Title A–Z. Pinned rows retain their saved order.

First slice: inline review rows use newest completed assistant reply first. Unknown reply times stay last; ties use stable session identity. Reading and renaming do not bump rows.

Recommended next choices: oldest reply first for clearing backlog, newest reply first for checking fresh work, and Title A–Z for finding a named task. Label this “AI’s last reply,” since it is not a timestamp proving the task completed. A true “Waiting longest” sort needs a durable review-entry clock.

03 · review-unread-state

Unread and review answer different questions

  • Unread: there is a result you want to return to. Opening it clears the normal read marker.
  • Ready for review / In review / Changes requested: a persistent workflow marker, changed explicitly.
  • Approved: removes the review obligation, while a separate unread marker may remain.
  • Needs input: a human response or action is needed. A chooser is optional. It is not completion or approval.

The existing PR103 Status menu already persists review flags through reading. Inline rows reuse that menu and the existing tab unread action, with both right-click/long-press and a visible actions button. Real permissions are never cleared by a manual status change.

Recommended refinement: call the combined group “To review”; show each row’s actual state. The existing “Ready to review” bucket also contains unread completions and In review / Changes requested.

04 · review-side-tabs

One navigation column, with an optional review view

The inline list already provides vertical navigation for reviewing. Use it before adding another permanent rail beside the workspace and Explorer sidebars.

Recommended optional mode: “Review workspace” temporarily scopes the existing left column to the active workspace’s review list, with a clear Back to workspaces action. A later “Tabs on the side” layout should replace the horizontal strip using that same column, never add a third column.

Preserve selected tab, split-pane identity, drag order, keyboard shortcuts and saved horizontal layout when switching back. Files, terminals and browser tabs need a clear All tabs view; a review list must not make them disappear. On compact screens, retain the existing sidebar overlay.
